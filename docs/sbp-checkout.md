# Оплата заказа через СБП

СБП реализована отдельным способом оплаты через страницу ЮKassa: сервер создаёт платёж с `payment_method_data.type=sbp`, `confirmation.type=redirect` и `capture=true`. После создания заказа клиент проверяет его в модалке и нажимает «Оплатить СБП», только тогда браузер открывает `confirmation_url`. Карточный платёж остаётся двухэтапным и использует прежний embedded-виджет. Сервер берёт адрес возврата из `Origin` запроса (или `Referer`, если `Origin` отсутствует), сверяет его с разрешёнными адресами и возвращает клиента сразу в `/{city}/zakazy?sbp_return=1`. На странице «Мои заказы» общий обработчик для мобильной и десктопной версий проверяет статус через сервер и считает заказ оплаченным только после обработки платежа сервером. Старые возвраты на главную с `sbp_return=1` перенаправляются в «Мои заказы».

Способ оплаты показывается покупателям, только если при сборке фронтенда задано `NEXT_PUBLIC_SBP_ENABLED=true`, а на рабочем `laravel-api-site` задано `SBP_ENABLED=true`. Для серверного переключателя нужен уникальный `SBP_RETRY_SECRET` длиной от 32 символов. При сборке через GitHub Actions значение берётся из **Repository variable** `NEXT_PUBLIC_SBP_ENABLED`; изменение `.env` на сервере после сборки образа не влияет на браузерный код. После изменения переменной нужно заново запустить сборку и выложить новый образ. По умолчанию оба переключателя выключены. Хранить `SBP_RETRY_SECRET` следует только на сервере.

До включения обоих переключателей необходимо подтвердить у ЮKassa подключение СБП для магазинов всех участвующих кафе. Также нужно проверить доставку webhook ЮKassa в `laravel-api-site`, обработку оплаченного СБП и чеков в Chef, отмену и возврат. Тестовый магазин ЮKassa не позволяет провести СБП-платёж; автоматические проверки используют подменённый банк и не создают заказы.

Каждое нажатие «Проверить заказ» создаёт новый заказ через `create_order_pre`. Сайт не предлагает продолжать оплату прежнего заказа. Данные последнего СБП-заказа хранятся в браузере до 15 минут только для проверки статуса после возврата из банка; `sbpPaymentStatus` возвращает успех после подтверждения банком и локальной обработки. После истечения этого срока пользователь может проверить заказ в личном кабинете. Серверный `retry_sbp_payment` остаётся доступным для обратной совместимости, но сайт его не вызывает.
