# Выбор даты и времени предзаказа

Окно «Выберите дату и время» в оформлении заказа: `modules/cartForm/dataTimePicker.js`,
загрузка слотов — `getTimesPred` в `components/store.js` (запрос `cart.get_times_pred`).
Слоты считает сервис очереди на `jacochef.ru`, бэкенд сайта обращается к нему на каждый запрос.

## Правила — с 11 ноября 2026

- **Одна смена даты — один запрос.** Колесо подписывается на события прокрутки один раз и
  снимает подписку при закрытии окна. Раньше обработчики добавлялись при каждой смене даты,
  и каждая следующая прокрутка отправляла на один одинаковый запрос больше (стрелкой —
  два запроса уже с первого нажатия).
- **Одинаковый запрос не дублируется.** Пока запрос с той же точкой, датой, типом заказа и
  корзиной выполняется, второй такой же не отправляется. После ответа вопрос задаётся
  заново: слоты со временем меняются.
- **Применяется ответ только последнего запроса.** Ответ прежней даты, пришедший позже, не
  подменяет слоты выбранной даты и не показывает ошибку.
- **Отказ бэкенда повторяется один раз.** Если бэкенд ответил `st: false`, запрос уходит ещё
  раз, и ошибка показывается только после второго отказа; список времени при этом
  очищается, как и раньше. Сетевые сбои (`transport_error` в ответе `api()`) дополнительно
  не повторяются — их повторяет сам `api()`.
- Если на сегодня слотов нет, показываются завтрашние, а «Сегодня» убирается из дат — без
  изменений.

## Зачем

11 ноября 2026 сервер сайта терял часть исходящих соединений, и примерно каждое четвёртое
обращение к сервису очереди обрывалось через 3 секунды. Из-за накопленных обработчиков одна
прокрутка даты отправляла несколько запросов; отказ любого из них, пришедший последним,
стирал уже показанное время и гасил кнопку «Выбрать». Теперь разовый сбой связи клиент не
замечает, кроме задержки в несколько секунд.

Причину сбоев связи это не устраняет. На стороне бэкенда запрос слотов и проверка времени
предзаказа при создании заказа по-прежнему делают одну попытку.
