# Проверка адресов доставки

Исправление production-сценария выбора адреса согласовано пользователем отдельно от Storybook.

Подсказка Яндекса передаётся в `profile/check_street` с разделителем `, ` между районом и улицей. Улица имеет приоритет над населённым пунктом независимо от порядка компонентов и позиции `kind`. Выбранный город повторно не добавляется; другой населённый пункт сохраняется. Для нескольких `DISTRICT` используется последний, как в прежнем коде, чтобы не добавлять административные префиксы к кварталу.

Ошибка API показывает серверный `text`. Новый поиск очищает прежний адрес и `street_id`, завершение запроса всегда снимает загрузку.

Запуск без реальных API-запросов:

```sh
npx vitest run --config tests/address/vitest.config.mjs
```

Тесты покрывают бульвар Гая / Рябиновый бульвар, порядок компонентов, несколько районов, населённые пункты, пустые данные, ошибку API / исключение, выбор одного и нескольких адресов. Состояние store проверено для ширины 375 / 768 / 1280; отдельная визуальная проверка интерфейса этими тестами не выполняется.

## Повторная проверка подъезда (2026-09-17)

У ответа из БД (`type=1`) поле `street` уже содержит `city_name_dop`, а у геокодера (`type=2`) эти части разделены. Обе формы адреса раньше повторно добавляли район в подпись и в `check_street` при смене подъезда. Теперь `getAddressStreet` соединяет части только если уточнение отсутствует, а `getAddressLabel` использует ту же строку для отображения. Исправлены общая форма `profile/modalAddr.jsx` (профиль и оформление заказа) и мобильная `address/modalAddressMobile.js`.

Регрессионные тесты используют оба формата ответа, включая реальные формы полей для бульвара Гая, 4 и бульвара Кулибина, 12; повторный запрос сохраняет город, дом и подъезд. Store-сценарий проверяется на 375 / 768 / 1280. Визуальный рендер компонентов этими тестами не проверяется. Ошибки внешнего геокодера по-прежнему возвращаются пользователю; проверка подъезда и зоны доставки не обходится.

После неудачной проверки подпись сохраняется в `choose_street`, но `chooseAddrStreet` остаётся пустым и `street_id=0`. Явная очистка/смена города/загрузка формы сбрасывает черновик. Убрано обрезание `street.split(', ')[1]` при открытии существующего адреса: общая сборка поддерживает полное название и сохраняет дополнительные части. Добавлен SSR-рендер реальных двух форм с mock внешних UI и карты, который проверяет отсутствие дубля квартала и сохранённую подпись адреса после ошибки на 375 / 768 / 1280. Это проверка разметки, не визуальная проверка расположения элементов.

Результат адресного набора: 50 тестов прошли (3 файла). Desktop / Tablet / Mobile: сценарии store и SSR-разметка passed; визуальный layout в браузере в этом наборе не проверяется.

## Ручной ввод и подъезд (2026-09-17)

`addressInput` — единственный черновик текста; `addressEntrance` — текущий подъезд. Изменение текста сразу снимает старое подтверждение и маркер. Подсказку можно выбрать мышью/клавиатурой, но это больше не обязательно: Enter или уход из поля проверяют введённую строку. Подъезд проверяется после паузы 350 мс либо при уходе из поля; смена города и закрытие формы отменяют таймеры. Пустое поле при обычном уходе не отправляет проверку.

Общий `ui/useAddressInput.js` используется формой профиля на ПК/планшете, мобильной формой и обоими селекторами адреса для корзины. Компонентные сценарии запускаются в настоящем Chrome с реальными MUI `Autocomplete`/`TextField`; карта, оболочки модалок и граница store подменены. Тесты проверяют DOM-события и вызовы действий, без реальных API-запросов и сохранения адресов. Отдельный `addressDraft.test.js` проверяет настоящий store, запоздалые ответы и защиту сохранения.

```sh
# Установленный Chrome; без переменной используется Chromium из Playwright.
ADDRESS_BROWSER_CHANNEL=chrome npx vitest run --config tests/address/vitest.browser.config.mjs
npx vitest run --config tests/address/vitest.config.mjs
```

Покрытие: ввод `58А → 58`, подъезд `2` и быстрый ввод `11`, Enter, blur, мышь, ArrowDown + Enter, очистка, смена города, отмена поиска при закрытии. Desktop 1280 / Tablet 768 / Mobile 375: проверки событий passed. Проверка внешнего вида реальной страницы и живого геокодера не входит в этот набор. Результат: 24 браузерных теста и 83 теста Node прошли. Служебные результаты находятся под `.codex/`.
