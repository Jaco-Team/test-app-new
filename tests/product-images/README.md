# Проверка изображений товаров

Инструменты работают локально и не изменяют Object Storage/S3.

## Read-only аудит CDN

Команда выполняет только `HEAD`-запросы, проверяет существование вариантов, размер, MIME-тип и кеширующие заголовки:

```bash
npm run images:audit -- --id Madeira_set --output /tmp/jaco-image-audit.json
```

Несколько товаров передаются через запятую в `--ids`. Параметры `--widths` и `--formats` позволяют ограничить матрицу. Режим `--strict=true` возвращает ненулевой код, если вариант отсутствует.

## Локальное сравнение качества

Команда принимает исходный файл или директорию, создаёт варианты только в указанной локальной директории и формирует `report.json` и `report.csv`:

```bash
npm run images:benchmark -- \
  --input /tmp/jaco-image-sources \
  --output /tmp/jaco-image-benchmark
```

По умолчанию сравниваются:

- WebP quality 70, 75, 80, 85, 90;
- JPEG quality 75, 82, 90;
- AVIF quality 45, 55, 65;
- ширины 366, 466, 585, 732, 875, 1168 и 1420 пикселей.

Отчёт содержит размер файла, байты на пиксель, время кодирования и декодирования, MSE, PSNR и экономию относительно WebP quality 90 того же размера.

PSNR нужен для первичного ранжирования, но не заменяет ручную проверку контактных листов. Для корректного сравнения следует использовать оригиналы, а не повторно сжатые CDN-варианты. Рекомендуемая выборка — 10–20 светлых, тёмных и текстурных изображений разных категорий.

## Ограничения

- Результаты времени сравнимы только внутри одного запуска на одном компьютере.
- AVIF может дать меньший файл ценой более долгого кодирования или декодирования.
- Ошибочный `Content-Type` фиксируется как предупреждение и должен исправляться в metadata объектов отдельной backend/infrastructure задачей.
- Загрузка результатов в S3 данным набором скриптов не поддерживается намеренно.
